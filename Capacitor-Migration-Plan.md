# Capacitor migration plan — Jugalbandhi Self

This is the plan for moving from a Bubblewrap TWA pointing at `rahilmundkur.github.io` to a single Capacitor project that produces both an Android app (with Play Asset Delivery for FR/HI/TH audio) and an iOS app (with On-Demand Resources for the same audio). The web codebase stays the same — `index.html` and friends — bundled inside both native packages.

The companion scaffold lives at `capacitor-project/` in this folder.

---

## Critical pre-flight: sync `reader.html` and `index.html`

The Bubblewrap manifest points at `/jugalbandhi-self/reader.html`. That file on GitHub Pages does NOT have any of the recent patches (custom note modal, fixed annotation toolbar position, audio-pack probe, `var(--text)` fix, search escape fix, etc.). The patched code is in `index.html`.

**Before doing anything else**, decide which file is the source of truth. Two options:

1. **Recommended**: Make `index.html` the canonical file. Replace `reader.html` with a copy of `index.html`, push to GitHub Pages, and let the live TWA users get the fixes immediately. Then start the Capacitor migration.

2. Skip GitHub Pages updates and only fix things in the Capacitor build. Live TWA users keep running unpatched code until they update to the new app.

Either way, the Capacitor project uses `index.html` as input.

---

## Architecture overview

You're moving from this:

```
Bubblewrap TWA (Android only)
    ↓
WebView opens https://rahilmundkur.github.io/jugalbandhi-self/reader.html
    ↓
All assets (HTML, JS, audio) served over the network from GitHub Pages
```

To this:

```
Capacitor app (Android + iOS)
    ↓
WebView opens file:///<bundle>/index.html  (web app bundled inside the package)
    ↓
HTML/JS/CSS load locally — instant, offline-capable
    ↓
English audio: bundled in the package (under www/audio/en/)
    ↓
FR/HI/TH audio: native asset packs / ODR — downloaded from Play / App Store
    ↓
JS calls window.Capacitor.Plugins.AudioPack.getFileUri(...) for those languages
```

The web code is identical between the two builds. The only difference is a small JS shim (added to `index.html`) that detects `window.Capacitor` and routes audio fetches through a native plugin instead of fetching from a relative path.

## Migration steps

### 1. Install Node 18+, Capacitor CLI, and Xcode + Android Studio

```bash
# Mac with Homebrew
brew install node
node -v   # should be 18+

# Install Capacitor CLI globally (optional — npx works too)
npm install -g @capacitor/cli
```

You also need:
- **Xcode 14+** (App Store) — install from the Mac App Store
- **Android Studio 2024.x** with the Android SDK + emulator
- **CocoaPods** for iOS native dependencies: `brew install cocoapods`

### 2. Set up the Capacitor project

```bash
cd /Users/rahilmundkur/Documents/JUGALBANDHI/Translations/APIDeepL/capacitor-project

# Install JS dependencies (already declared in package.json)
npm install

# Populate www/ with the web app
mkdir -p www
cp ../index.html              www/
cp ../manifest.json           www/
cp ../sw.js                   www/
cp -r ../icons                www/
cp -r ../Cormorant_Garamond,Inter,Noto_Serif www/
mkdir -p www/audio
cp -r ../audio/en             www/audio/   # English bundled in app

# Add the iOS and Android platforms (this generates ios/ and android/ folders)
npx cap add android
npx cap add ios

# Sync — copies www/ into both native projects + installs CocoaPods etc.
npx cap sync
```

### 3. Build the audio-pack-bridge plugin

The `audio-pack-bridge/` folder in the scaffold already contains:

- `src/definitions.ts` — TypeScript interface (what the JS sees)
- `src/web.ts` — web fallback (used in browser)
- `android/.../AudioPackPlugin.kt` — Android implementation using `AssetPackManager`
- `ios/Plugin/AudioPackPlugin.swift` — iOS implementation using `NSBundleResourceRequest`

Build the plugin once before using it:

```bash
cd audio-pack-bridge
npm install
npm run build       # produces dist/ for the TS interface
cd ..

# Tell the main Capacitor app about the local plugin
npm install ./audio-pack-bridge

npx cap sync
```

### 4. Configure Android Play Asset Delivery

Edit `capacitor-project/android/app/build.gradle` to declare three asset packs:

```gradle
android {
    // ... existing config ...
    assetPacks = [':audio_fr', ':audio_hi', ':audio_th']
}
```

Edit `capacitor-project/android/settings.gradle` to include the pack modules:

```gradle
include ':app', ':audio_fr', ':audio_hi', ':audio_th'
project(':audio_fr').projectDir = file('../audio-packs-android/audio_fr')
project(':audio_hi').projectDir = file('../audio-packs-android/audio_hi')
project(':audio_th').projectDir = file('../audio-packs-android/audio_th')
```

The scaffold already has `audio-packs-android/audio_{fr,hi,th}/` set up — you just need to copy the MP3s in:

```bash
cp -r ../audio/fr capacitor-project/audio-packs-android/audio_fr/src/main/assets/audio/
cp -r ../audio/hi capacitor-project/audio-packs-android/audio_hi/src/main/assets/audio/
cp -r ../audio/th capacitor-project/audio-packs-android/audio_th/src/main/assets/audio/
```

Each pack module is configured for **fast-follow** delivery, meaning Play downloads it automatically right after install before first launch on most devices.

Add the PlayCore dependency to `capacitor-project/android/app/build.gradle` under `dependencies {`:

```gradle
implementation 'com.google.android.play:asset-delivery-ktx:2.2.2'
```

### 5. Configure iOS On-Demand Resources

ODR is configured inside Xcode (it's metadata stored in the project file, not a config file you can easily edit in a text editor). Steps:

```bash
cd capacitor-project
npx cap open ios
```

In Xcode:

1. Add the FR/HI/TH MP3 folders to the project: **File → Add Files** → select `audio/fr`, `audio/hi`, `audio/th` from your APIDeepL folder. In the dialog, choose **Create folder references** (not "Create groups") and check "Copy items if needed".
2. Select all the French MP3 files in the navigator. In the **File Inspector** (right sidebar), expand **On Demand Resource Tags** and add the tag `audio_fr`. Repeat with `audio_hi` for Hindi and `audio_th` for Thai.
3. **Project Settings → Resource Tags** — leave each tag in the **Download Only On Demand** category (NOT "Initial Install" and NOT "Prefetched"). The user-driven download flow requires the OS to keep these resources off-device until the in-app Download button asks for them.

Apple delivers ODR resources from their CDN at no cost to you. With "Download Only On Demand", nothing downloads at install — the bridge plugin's `requestPack(lang)` call (triggered by the in-app Download button) is what fetches them.

### 6. JS shim and Download-audio button (already in `index.html`)

The patched `index.html` already contains:

- `_probeAudioPack(lang)` — checks the AudioPack plugin first, falls back to a fetch probe for plain browsers.
- `_resolveAudioUrl(lang, ch, p, speaker)` — calls `AudioPack.getFileUri` natively, returns relative path on web.
- `downloadAudioPack()` — triggered by the visible Download button next to Listen. Calls `AudioPack.requestPack(lang)` natively; on web, just confirms the file is reachable.
- `_updateAudioPackButton()` — shows/hides the button based on current language and pack state. Called on language change, on app load, and after every download attempt.
- The "audio not on device" modal now has a **Download now** action that calls the same flow the visible button uses.

The visible Download button (`#btn-audio-pack-dl`) lives in the reader toolbar between the Listen button and the bookmark buttons. It is hidden when:

- Current language is English (audio is bundled).
- Pack state is `'available'` (already downloaded).

It is visible (and enabled) when:

- Current language is FR/HI/TH and pack state is `'missing'`, `'unknown'`, or undefined.

While downloading, the button stays visible but disabled with a spinner and "Downloading…" label. On success it briefly shows a toast and then hides. On failure it shows "Download failed — retry" for a few seconds before reverting.

After editing `index.html` for any reason, run `npx cap sync` to copy changes into both native projects.

### 7. First run on emulators

```bash
# Android emulator
npx cap run android

# iOS simulator
npx cap run ios
```

You should see the cover screen, be able to open chapters, switch language. With the Android emulator (must be a Google Play image, see `Emulator-AssetPack-Testing.md`), you can test the FR/HI/TH packs using `bundletool --local-testing`. With the iOS simulator, ODR resources are not actually downloaded but the bridge's "available" responses are mocked — you can verify the code paths by running with `?perf=1` and watching `[jbMark]` logs.

### 8. Signing and store submission

**Android.** Reuse your existing keystore at `jugalbandhi-android/android.keystore` so the app updates flow naturally on Play. Add to `capacitor-project/android/key.properties`:

```
storeFile=/Users/rahilmundkur/Documents/JUGALBANDHI/Translations/APIDeepL/jugalbandhi-android/android.keystore
storePassword=<your keystore password>
keyAlias=android
keyPassword=<your key password>
```

Then in Android Studio: **Build → Generate Signed Bundle / APK → AAB**.

**iOS.** You need an Apple Developer Program membership ($99/year) to submit to the App Store. In Xcode: **Signing & Capabilities** → set your team → **Product → Archive** → **Distribute App → App Store Connect**.

### 9. Store-submission readiness checklist

| Task | Android | iOS |
|---|---|---|
| Privacy policy URL | required if collecting any data | required for any app |
| Data safety / privacy declarations | Play Console → App content | Xcode → "Privacy Manifest" |
| Screenshots | 2-8 per device size | 5 per device size |
| App description, short description | Play Console listing | App Store Connect listing |
| Age rating questionnaire | Play Console | App Store Connect |
| Content rights confirmation | Play Console | App Store Connect |
| Tester invitations | Play Console internal track | TestFlight |

Both stores require an active privacy policy URL accessible from a stable host. Your existing `privacy-policy.html` works — just publish it on a stable URL (GitHub Pages still fine for this).

## Common gotchas

**`npx cap sync` doesn't pick up my JS changes.** Capacitor copies `www/` into both native projects on `sync`. If you edit `www/index.html`, run `sync` again. Or, for fast iteration: enable Capacitor's live-reload — `npx cap run android --live-reload` runs the app pointing at a local dev server, so you can edit and reload without rebuilding.

**iOS "code signing" errors.** Almost always a team / provisioning profile issue. In Xcode: General tab → Signing & Capabilities → set Team to your Apple Developer team. Xcode auto-creates a provisioning profile.

**Asset pack fails to install on emulator.** Use a Google Play system image, not a Google APIs image. See `Emulator-AssetPack-Testing.md` for full details.

**iOS ODR resources don't download in the simulator.** Expected — simulators don't fetch ODR. With "Download Only On Demand" tags, the simulator behaves correctly for the missing-pack flow: the Download button appears, tapping it triggers a no-op success because the resource is "already in the bundle" from the simulator's perspective. For a real on-the-wire ODR test, ship to TestFlight and install on a real device.

**Pack progress isn't shown.** The current Download button shows a generic spinner ("Downloading…") while the request is in flight. Both Play's `AssetPackManager` (Android) and `NSBundleResourceRequest` (iOS) report fractional progress. To surface a percentage, extend the bridge plugin to emit `progress` events via Capacitor's `notifyListeners` API and add a JS listener that updates the button label. About 30 lines of code each side; not required for v1.

**Apple App Review rejects the app for "Minimum Functionality."** This is the most common rejection for web-shell apps. To pass: emphasize the offline reading capability, native annotations, native audio playback, and the on-device data persistence. Don't describe it as "a web app" in the listing — describe it as "a native reading experience for iPhone and iPad with offline support."

**Bundle size warning at submission.** Both stores show the AAB / IPA size at submission time. With audio packs separated, your base app should be under 50 MB. If it's over 100 MB, double-check that the audio is in the pack modules and not also in `www/audio/{fr,hi,th}/`.
