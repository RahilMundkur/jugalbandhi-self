# Jugalbandhi Self — Capacitor project

Cross-platform native shells (iOS + Android) wrapping the existing web app.

## Quick start

```bash
# 1. Install JS deps
npm install

# 2. Populate www/ with the patched index.html and supporting assets
npm run copy-www

# 3. Add native platforms (generates ios/ and android/ folders)
npx cap add android
npx cap add ios

# 4. Build the local audio-pack-bridge plugin
cd audio-pack-bridge && npm install && npm run build && cd ..
npm install ./audio-pack-bridge

# 5. Sync www/ + plugins into native projects
npx cap sync

# 6. Run on emulator
npx cap run android        # or npx cap run ios
```

For full setup, including signing, asset-pack configuration, and store
submission, see `../Capacitor-Migration-Plan.md`.

## Folder layout

```
capacitor-project/
├── package.json                      ← top-level deps + scripts
├── capacitor.config.ts               ← Capacitor config (appId, webDir…)
├── www/                              ← Web app (input — symlink or copy)
├── audio-pack-bridge/                ← Local Capacitor plugin
│   ├── src/                          ← TS interface + web fallback
│   ├── android/                      ← Kotlin: Play Asset Delivery
│   └── ios/                          ← Swift: On-Demand Resources
├── audio-packs-android/              ← Gradle modules for FR/HI/TH packs
│   ├── audio_fr/
│   ├── audio_hi/
│   └── audio_th/
├── android/                          ← generated by `npx cap add android`
└── ios/                              ← generated by `npx cap add ios`
```

## Development loop

```bash
# Edit web code in ../index.html (the canonical file lives one level up)
# Re-copy and re-sync:
npm run copy-www && npx cap sync

# Or use live-reload (faster — runs the app pointing at a dev server):
npm run live:android
```

## What this project changes about your existing setup

- **Web hosting becomes optional.** The web app is bundled inside the apps
  via `www/`. You can keep deploying to GitHub Pages as a free web demo
  alongside the apps, or retire it.
- **`reader.html` becomes redundant.** The Capacitor build always opens
  `www/index.html`. Delete `reader.html` from GitHub Pages once both apps
  are live.
- **`jugalbandhi-android/`** (the Bubblewrap project) becomes a backup.
  Capacitor regenerates the entire `android/` folder via `npx cap add`.
  Keep the keystore from Bubblewrap — Capacitor reuses it for signing.

## What this project preserves

- Same `applicationId` (`com.rahilmundkur.jugalbandhiself`) — Play sees
  this as a normal update of the existing app.
- Same signing key — set up in `android/key.properties` after the first
  `cap add android`.
- All localStorage data, IndexedDB caches, annotations, bookmarks — they
  live inside the WebView's storage which survives the TWA→Capacitor
  switch on the same package id.
- Same web code (HTML/JS/CSS), just bundled.
